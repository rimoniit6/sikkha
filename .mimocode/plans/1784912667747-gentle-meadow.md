# Blog Block Editor — Fully Independent Implementation Plan

## Goal

Replace Blog's dependency on the shared `src/components/ui/content-block-*` system with a fully independent Blog-owned block editor that mirrors the Lecture UX. Zero Lecture files touched. Zero shared block imports.

---

## Architecture

### New Directory

All new Blog block files go in: `src/features/blog/blocks/`

```
src/features/blog/blocks/
├── blog-block-types.ts          # Blog's own ContentBlock union, registry, ID generator
├── blog-block-factory.ts        # createBlogBlock()
├── blog-block-serializer.ts     # serializeBlogBlocks() / deserializeBlogBlocks()
├── blog-block-utils.ts          # headingsFromBlogBlocks(), processBlogContentBlocks()
├── BlogBlockEditor.tsx          # Main editor (exports default)
├── BlogAddBlockMenu.tsx         # Add Block grid menu
├── BlogBlockItem.tsx            # Single block wrapper (header + toolbar + content)
├── BlogBlockPreview.tsx         # Preview renderer for all block types
├── BlogHeadingBlockEditor.tsx   # Heading block editor
├── BlogTextBlockEditor.tsx      # Text block editor
├── BlogImageBlockEditor.tsx     # Image block editor
├── BlogMathBlockEditor.tsx      # Math block editor
├── BlogCodeBlockEditor.tsx      # Code block editor
├── BlogDataBlockEditor.tsx      # Data table block editor
├── BlogRichTextBlockEditor.tsx  # Rich text (TipTap) block editor
├── BlogPdfBlockEditor.tsx       # PDF block editor
├── BlogLinkBlockEditor.tsx      # Link block editor
├── BlogMindMapBlockEditor.tsx   # Mind map block editor
└── index.ts                     # Public barrel export
```

## Step-by-Step Implementation

### Step 1: Blog Block Types (`blog-block-types.ts`)

Copy the `ContentBlock` union type from `content-block-types.ts` but rename to `BlogContentBlock`. Keep the same 11 block types with identical shapes:

```typescript
export type BlogContentBlock =
  | { id: string; type: 'heading'; level: number; content: string }
  | { id: string; type: 'text'; content: string }
  | { id: string; type: 'image'; url: string; caption: string }
  | { id: string; type: 'math'; content: string }
  | { id: string; type: 'data'; headers: string[]; rows: string[][]; caption: string }
  | { id: string; type: 'code'; language: string; content: string }
  | { id: string; type: 'divider' }
  | { id: string; type: 'pdf'; url: string; title: string }
  | { id: string; type: 'link'; url: string; label: string; description: string }
  | { id: string; type: 'richtext'; content: string }
  | { id: string; type: 'mindmap'; data: string; title: string }
```

Also include:
- `BlogMindMapNode` interface
- `blogBlockTypeConfig` registry (same 11 entries with same icons/colors/labels)
- MindMap helper functions (`parseBlogMindMap`, `addBlogMindMapChild`, etc.)

**External imports allowed**: `lucide-react` icons only. No imports from `content-block-types.ts`.

### Step 2: Blog Block Factory (`blog-block-factory.ts`)

Copy `generateId()` and `createBlock()` as `blogGenerateId()` and `createBlogBlock()`. Same logic, independent implementation.

**No imports from shared block files.**

### Step 3: Blog Block Serializer (`blog-block-serializer.ts`)

Copy `serializeBlocks()` and `deserializeBlocks()` as `serializeBlogBlocks()` and `deserializeBlogBlocks()`. Same JSON.stringify/parse logic with fallback.

**No imports from shared block files.**

### Step 4: Blog Block Utils (`blog-block-utils.ts`)

Copy `headingsFromBlocks()` as `headingsFromBlogBlocks()`. Same logic for extracting h2/h3 for TOC.

**No imports from shared block files.**

### Step 5: Blog Block Editors (11 files)

Create one file per block type. Each is a self-contained editor component.

| File | Source Reference | Notes |
|------|-----------------|-------|
| `BlogHeadingBlockEditor.tsx` | Lines 49-83 of `content-block-editor.tsx` | Level selector + input |
| `BlogTextBlockEditor.tsx` | Lines 85-101 | Textarea with math hint |
| `BlogImageBlockEditor.tsx` | Lines 103-120 | Uses shared `ImageUploader` (UI component, not block system) |
| `BlogMathBlockEditor.tsx` | Lines 122-164 | Uses `MathBlock` from `math-block.tsx` (renderer, not block system) |
| `BlogCodeBlockEditor.tsx` | Lines 211-232 | Language input + textarea |
| `BlogDataBlockEditor.tsx` | Full copy of `DataBlockEditor.tsx` | Table editor with Excel import |
| `BlogRichTextBlockEditor.tsx` | Full copy of `RichTextBlockEditor.tsx` | TipTap editor with toolbar |
| `BlogPdfBlockEditor.tsx` | Lines 166-183 | ImageUploader for PDF |
| `BlogLinkBlockEditor.tsx` | Lines 185-209 | URL + label + description inputs |
| `BlogMindMapBlockEditor.tsx` | Full copy of `MindMapBlockEditor.tsx` | Markmap editor + preview |

**Critical**: Each editor imports `BlogContentBlock` from `./blog-block-types` (NOT from shared). The `BlogImageBlockEditor` imports `ImageUploader` from `@/components/ui/image-uploader` — this is a UI component, not part of the block system, so it's safe.

**RichTextBlockEditor dependency**: Uses `@tiptap/*` packages, `useUploadThing` from `@/lib/upload/client`, `ImageResizeNodeView` from `@/components/ui/image-resize-node-view`. These are UI/utility dependencies, not block system dependencies. The blog copy may import them.

**DataBlockEditor dependency**: Uses `safeParseExcelClient` from `@/lib/excel-parse`. Safe to import.

**MindMapBlockEditor dependency**: Uses `Markmap` from `markmap-view`, `ToolbarButton` from the rich text editor. Blog's copy will import `ToolbarButton` from `./BlogRichTextBlockEditor`.

### Step 6: Blog Block Preview (`BlogBlockPreview.tsx`)

Imports `BlogContentBlock` and `blogBlockTypeConfig` from `./blog-block-types`. Imports individual block editors from their respective files. Imports `BlogBlockPreview` from `./BlogBlockPreview`.

### Step 8: Blog Add Block Menu (`BlogAddBlockMenu.tsx`)

Copy the `AddBlockMenu` from `content-block-editor.tsx` (lines 560-654). Grid of block type buttons with animation.

Imports `BlogContentBlock` and `blogBlockTypeConfig` from `./blog-block-types`.
